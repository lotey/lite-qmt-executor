# 新手开发指南

面向第一次接触 QMT/miniQMT 的开发者，解答环境搭建和常见疑问。

---

## miniQMT 是什么

miniQMT 是券商提供的**量化交易终端**，本质是一个 Windows 桌面程序。它提供：
- 交易通道（下单/撤单/查持仓/查委托）
- 实时行情（Level1 tick 数据）
- Python SDK（xtquant）用于程序化调用

你可以把它理解为"一个带 API 的炒股软件"。

## QMT 和 miniQMT 的区别

券商提供的 QMT 客户端实际上有两种模式，很多人搞混：

| | QMT（完整模式） | miniQMT（独立交易模式） |
|---|---|---|
| 界面 | 完整的交易界面 + K线 + 策略编辑器 | 精简窗口，无交易界面，只负责维持连接 |
| 用途 | 手动交易 + 在内置编辑器里写策略 | 保持登录状态，给外部程序提供交易通道 |
| 编程方式 | 只能在 QMT 内置编辑器里写，受限于它的框架 | 你的程序完全独立，通过 xtquant SDK 调用 |
| 灵活性 | 低（必须用它的回调框架、不能装外部库） | 高（普通 Python 项目，随便装库、随便写） |
| 本项目需要 | 首次初始化时需要（下载Python环境） | ✅ 日常运行用这个模式登录 |

**关键区别**：
- QMT 完整模式 = 在它的"沙盒"里写策略，受限很大
- miniQMT = 只提供交易通道，你的程序完全自由

**本项目使用的是 miniQMT**。你只需要让 miniQMT 在后台运行（提供交易通道），你的 Python 程序在外面独立运行、自由开发。

⚠️ **开通权限时必须确认开通的是 miniQMT 权限**。只有普通 QMT 权限是不够的，普通 QMT 只能在内置编辑器里写策略，不能被外部程序调用。

## 通信调用关系

很多人第一次接触不理解"程序怎么能炒股"，这里说清楚整个链路：

```
你的 Python 程序（本项目 / 你自己写的程序）
    │
    │  调用 xtquant SDK（Python 库，本地函数调用）
    ▼
xtquant SDK
    │
    │  本地进程间通信（连接 miniQMT 客户端）
    ▼
miniQMT 客户端（必须保持运行、已登录）
    │
    │  网络连接（券商私有协议）
    ▼
券商柜台系统
    │
    │  报盘通道
    ▼
交易所（上交所 / 深交所）
```

**通俗理解**：
- miniQMT 客户端 = 你雇的"交易员"，它帮你连着券商和交易所
- xtquant SDK = 你跟交易员之间的"对讲机"
- 你的程序 = 你自己，通过对讲机告诉交易员"买什么、卖什么"

**所以前提条件**：
1. miniQMT 必须先启动并登录（交易员得先到岗）
2. 你的程序通过 xtquant 调用它（通过对讲机下指令）
3. 程序和 miniQMT 必须在**同一台 Windows 机器**上运行

## miniQMT 安装部署

### 第一步：开通量化权限

miniQMT 不是随便下载就能用的，需要向券商申请开通量化交易权限：

1. 联系你的券商客户经理，说"要开通 **miniQMT** 量化交易权限"（注意必须是 miniQMT，不是普通 QMT）
2. 券商通常会要求：
   - **资金门槛**：不同券商差异很大，有的要求 50 万资产，有的 10 万，有的免费开通
   - **签署协议**：部分券商需要签署《量化交易风险揭示书》或《程序化交易协议》
   - **绑定设备**：大部分券商要求绑定运行机器的 MAC 地址（网卡物理地址），只有绑定的机器才能登录
   - **其他材料**：个别券商可能要求提供交易经验证明等
3. 具体要求以你所在券商为准，直接问客户经理最快

**支持 miniQMT 的券商**（不完全列表）：国金、东北、华鑫、中泰、国盛、财通等。

**Tips**：
- 如果当前券商门槛太高或不支持，可以考虑新开一个支持的券商账户
- 绑定 MAC 地址后如果换电脑，需要联系客户经理重新绑定
- 开通后券商会给你 QMT 客户端的下载链接

### 第二步：下载安装 QMT 客户端

1. 从券商给的链接下载 QMT 安装包（通常叫"XX证券量化交易终端"）
2. 安装到任意目录，比如 `D:\证券QMT交易端\`
3. 安装完成后会有 `userdata_mini` 目录，这个路径后面要配到 `config.py`

**注意**：刚装完时 `bin.x64/Lib/site-packages/xtquant` 目录还不存在，需要完成第三步（初始化Python环境）后才会有。

### 第三步：首次启动下载 Python 环境

首次使用需要在 QMT 完整模式下初始化 Python 环境：

1. 打开 QMT 客户端，**不要勾选"独立交易"模式**，用完整模式登录
2. 进入量化/策略编辑界面，程序会提示下载 Python 环境
3. 点击确认，等待自动下载安装完成（xtquant SDK 会一起装好）
4. 下载完成后目录结构大致如下：
   ```
   D:\证券QMT交易端\
   ├── bin.x64\
   │   ├── Lib\
   │   │   └── site-packages\
   │   │       └── xtquant\        ← SDK 在这里
   │   └── ...
   ├── userdata_mini\              ← 这个路径要配到 config.py
   └── ...
   ```

**注意**：这一步只需要做一次。Python 环境只能在完整模式下下载，独立交易模式没有这个功能。初始化完成后，后续日常使用就不需要再打开完整模式了。

### 第四步：登录 miniQMT（日常使用）

初始化完成后，日常使用只需要登录独立交易模式：

1. 打开 QMT 客户端主程序
2. 在登录界面输入资金账号和密码
3. **勾选"独立交易"模式**（也叫"极简模式"/"mini模式"，不同券商叫法不同）
4. 点击登录
5. 登录成功后**保持窗口开着不要关**（miniQMT 进程必须存在，你的程序才能连上）。正常最小化放着不用管它即可。

**总结**：完整模式只在第一次初始化 Python 环境时用，之后每天只需要登录独立交易模式即可。

### 第五步：确认 userdata_mini 路径

登录成功后，找到 `userdata_mini` 目录的完整路径，填到 `app/config.py`：

```python
QMT_PATH = r'D:\证券QMT交易端\userdata_mini'
```

## 程序必须写在 QMT 内部吗？

**不需要。** 这是最常见的误解。

本项目（lite-qmt-executor）或者你自己开发的程序，都是**独立的 Python 程序**，放在任何目录都行。它通过 xtquant SDK 远程连接正在运行的 miniQMT 客户端，不需要把代码放到 QMT 安装目录里。

关系是这样的：

```
你的程序（任意目录）
    │
    │  通过 xtquant SDK 连接
    ▼
miniQMT 客户端（必须保持运行）
    │
    │  连接券商柜台
    ▼
交易所
```

唯一的要求是：**miniQMT 客户端必须先启动并登录**，你的程序才能连上。

---

## 能不能用外部 Python 库？

**完全可以。** 你的程序就是一个普通的 Python 项目，想装什么库就装什么库：

```bash
pip install numpy pandas requests flask websocket-client
```

唯一特殊的是 **xtquant 不要 pip 安装**。原因：
- xtquant 包含 `.pyd` 编译文件和 DLL，必须跟本地 QMT 客户端版本严格匹配
- pip 上的 xtquant 不是官方包，版本可能错配导致连不上 miniQMT
- 本项目的 `broker.py` 会自动把 QMT 安装目录下的 SDK 加到 `sys.path`，不需要你手动处理

所以规则很简单：**除了 xtquant 以外，其他库随便装**。

---

## Python 版本要求

- 推荐 Python 3.8~3.11，其他版本可能有兼容性问题
- 如果你本机有多个 Python 版本，用 3.8~3.11 范围内的即可
- QMT 自带的 Python（在 `bin.x64` 目录下）也能用，但不是必须用它

## 常见问题

### Q：启动报 "请确保miniQMT客户端已运行并登录"

miniQMT 客户端没启动，或者没登录。打开 QMT 客户端，用极简/mini模式登录后再启动程序。

### Q：启动报 "QMT路径不存在"

`config.py` 里的 `QMT_PATH` 路径写错了。确认路径指向 `userdata_mini` 目录，注意用原始字符串（`r'...'`）避免反斜杠转义问题。

### Q：启动报 "账户信息订阅失败"

`ACCOUNT_ID` 填错了。确认填的是资金账号（纯数字），不是手机号或身份证号。

### Q：ImportError: cannot import name 'xxx' from xtquant

xtquant SDK 版本和 QMT 客户端不匹配。确认没有 pip 安装过 xtquant：
```bash
pip uninstall xtquant
```
然后让 `broker.py` 自动加载 QMT 目录下的 SDK。

### Q：Flask 启动报 ImportError: cannot import name 'Container'

QMT 自带的 `site-packages` 里有老版本的 werkzeug，和系统装的 Flask 冲突。`broker.py` 已经处理了这个问题（用 `sys.path.append` 而不是 `insert`），如果还报错，确认你用的是最新版本的代码。

### Q：下单返回正数但实际是废单

这是 QMT 的坑。`order_stock` 返回正数只代表"接口调用成功"，不代表"单子有效"。必须事后查 `order_status`，57 就是废单。详见 `doc/qmt实盘调试文档.md`。

### Q：盘后能测试吗？

- 账户查询、持仓查询：盘后可以
- 行情查询：盘后返回收盘价
- 下单/撤单：盘后不行（交易所关了）
- 建议第一次完整测试在盘中 10:30~11:00 做

### Q：怎么调接口？有没有 HTTP API 或 REST 接口可以调？

miniQMT 本身不提供任何 HTTP/REST/WebSocket 接口。它走的是**本地进程间通信**，只能通过 xtquant 这个 Python SDK 在同一台机器上调用。

也就是说：
- xtquant SDK 只能在 miniQMT 运行的**同一台 Windows 机器**上使用
- 只支持 **Python** 语言调用，不能用 Java/Go/C# 等直接调 miniQMT
- 如果你的信号源或策略逻辑在其他机器/其他语言上，需要自己在 miniQMT 所在机器上搭一层中转服务（比如本项目提供的 HTTP API + WebSocket 就是干这个的——把 xtquant 本地调用包装成网络接口，让外部系统能远程触发交易）

**一句话总结**：和 miniQMT 交互的最底层程序，只能是 Python 开发、和 miniQMT 跑在同一台 Windows 电脑上，其他方式都不行。

### Q：能同时跑多个程序连同一个 miniQMT 吗？

可以，但不建议。多个程序同时下单可能导致资金/持仓冲突。本项目有单实例锁（端口占用），同一台机器不能重复启动。

### Q：Mac/Linux 能用吗？

不能。miniQMT 只有 Windows 版本，xtquant SDK 也只有 Windows 的 `.pyd` 文件。必须在 Windows 上跑。

如果你的开发环境是 Mac/Linux，可以：
- 在 Windows 实体机上部署运行（建议方案）
- 虚拟机或云服务器：部分券商会检测虚拟环境导致无法登录，请自行测试
- 本地开发逻辑代码，部署到 Windows 实体机上跑

### Q：需要一直开着电脑吗？

是的。miniQMT 客户端必须保持运行，你的 Python 程序也必须保持运行。建议：
- 用一台专门的 Windows 机器（台式机或云服务器）
- 设置开机自启动 miniQMT + 自动登录
- 用 `qmt-run.bat` 启动 Python 程序

### Q：断网了怎么办？

- miniQMT 断网后会自动重连券商
- 本项目的 WebSocket 客户端断线后也会自动重连
- 如果 miniQMT 彻底断开（比如券商维护），程序会检测到连接失败并退出，等网络恢复后重启即可

### Q：手续费怎么算？

跟你正常炒股一样，走券商的佣金费率。miniQMT 下单和手动在软件里下单没有区别，不额外收费。

## 推荐的开发流程

1. **先跑通默认策略**：改 config → 启动 → curl 发信号 → 看日志确认流程正确
2. **盘中实测一次**：用 1000 元真金白银跑一单，确认下单/成交/持仓/撤单全链路通
3. **再写自己的策略**：确认基础设施没问题后，再动策略代码
4. **小资金试跑一周**：1-2 万跑几天，观察策略行为是否符合预期
5. **逐步加仓**：确认稳定后再加大资金

不要跳步。很多人上来就写复杂策略，结果连 QMT 连接都没跑通。
