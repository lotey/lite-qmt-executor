# 定制开发指南

这份文档教你怎么基于本项目定制开发自己的交易执行器。

## 0. 你要先理解的几件事

**本项目 = 框架 + 默认策略**。框架部分（信号接入、调度、QMT 适配、通知接口）是不变的；策略部分是可替换的。

`main.py` 默认装配了一套**功能完整的默认策略**，位置在 `app/strategy/default/`：
- `AccumulateBuyStrategy` — 分档累积买入
- `OpenHighSellStrategy` — 9:30 高开止盈
- `ProfitTierSellStrategy` — 分档盈利止盈

也就是说，**你拿到代码不动任何 .py 文件，只把 `config.py` 里的 `QMT_PATH`/`ACCOUNT_ID` 改成自己的，`python main.py` 就能跑**。

### 信号怎么来

执行器自己**不产生**买入信号，等外部喂。两种入口**同时可用**，您可以根据网络拓扑和调用习惯自由选择：

| 入口 | 工作模式 | 适用网络与部署场景 | 信号流向 |
|---|---|---|---|
| **HTTP API** | **被动推送 (Push)** | 适合局域网集成（如同机部署）、定时脚本触发，或有内网穿透条件的公网推送。 | 外部系统 ──(POST)──► 执行器 |
| **WebSocket** | **主动订阅 (Pull)** | 适合执行器部署在内网且无公网 IP、免去内网穿透，直接主动订阅远程网关的信号流。 | 执行器 ──(Subscribe)──► 信号网关 |

HTTP 始终启动（端口 30015）。WebSocket 需要在 `config.py` 里配齐 `GATEWAY_HOST` / `GATEWAY_PORT` / `GATEWAY_TOKEN` 三个参数才会启动，不配就不连。

**局域网或本地调试/生产推荐 HTTP**：随时一条 POST/curl 就能触发，方便与您自研的本地量化选股程序集成。

**跨网或无穿透条件推荐 WebSocket**：执行器作为 client 主动连接远程 gateway，订阅指定 token 对应的信号源。此时 HTTP 接口仍然可用（可用于本地查询持仓/订单/手动撤单等管理操作）。

### 启动后会发生什么

1. 引擎启动，加载默认策略
2. HTTP 服务监听 30015 端口（始终启动）
3. 如果配了 WebSocket 三个参数，同时连接 gateway 订阅信号
4. 收到信号（HTTP 或 WebSocket 均可）→ 丢给 `AccumulateBuyStrategy` 处理
5. 同时 `OpenHighSellStrategy` 和 `ProfitTierSellStrategy` 后台跑着，按时间扫持仓卖出

整个过程**不需要你写一行 Python 代码**。

## 定制分四档

按改动量从小到大：

| 档位 | 改什么 | 难度 | 适用场景 |
|---|---|---|---|
| A. 不改 | 啥也不动 | ⭐ | 默认策略就符合你的预期 |
| B. 调参数 | 改 app/strategy/default/stg_config.py | ⭐ | 阈值、档位、金额、时间 |
| C. 替换通知 | 实现 `Notifier` | ⭐⭐ | 接钉钉、企微、IM |

## A. 不改任何代码

适合"默认策略的逻辑就是我想要的"——

- 一笔信号来了，涨幅 ≤2.5% 直接抢买；2.5%~4.0% 首笔保底+回撤加仓；>4.0% 等回落，回落至 3.5% 以内开始买入
- 9:30 开盘看持仓有没有高开 3.0% 以上的，是的话卖一半
- 盘中看持仓涨到 3.0% 卖一半，涨到 5.0% 再卖剩余一半，涨到 8.0% 全卖

如果这就是你想要的玩法：

1. 改 `app/config.py`：
   ```python
   QMT_PATH = r'你的QMT路径\userdata_mini'
   ACCOUNT_ID = '你的资金账号'
   BUY_ENABLED = True  # 调试确认无误后打开
   ```
2. 装依赖：`pip install -r requirements.txt`
3. 启动：`python main.py` 或双击 `qmt-run.bat`
4. **调试**：用 curl 自己构造信号丢给执行器，验证策略走通：
   ```bash
   curl -X POST http://localhost:30015/api/buy \
        -H "Content-Type: application/json" \
        -d "{\"code\":\"sz000001\"}"
   ```
   日志里能看到：信号入队 → 拿行情 → 走 INIT 分支 → 下单/进 ACCUMULATING 等等。
5. **生产**：配齐信号网关对应的 `GATEWAY_HOST/PORT/TOKEN`，重启即可。执行器会主动连网关订阅信号，HTTP 同时仍然可用。

完事。其他什么都不用碰。

## B. 调参数

如果默认策略**逻辑符合你的预期**，但**具体数字想换一换**——比如想把抢买阈值从 3% 改成 2%、单笔金额改成 5000、止盈档位变 3 档——直接改 `app/strategy/default/stg_config.py` 里的 `StgConfig` 配置类就行。

## C. 替换通知

**默认通知是 `ConsoleNotifier`**——只往日志打印，不发到任何外部。

如果你想盘中下单、止盈、异常这些事件**实时弹到手机**，就要换 Notifier。常见的有钉钉机器人、企微机器人。

### 第一步：写自己的 Notifier 类

新建一个文件 `my_notifier.py`（放哪都行，建议跟 main.py 同级）：

```python
import requests
from app.core.notifier import Notifier


class DingTalkNotifier(Notifier):
    """钉钉机器人通知器"""

    def __init__(self, webhook):
        self.webhook = webhook

    def push(self, level: str, msg: str):
        """框架要求实现这个方法。level 是 'INFO'/'WARN'/'ERROR'，msg 是消息正文。"""
        try:
            requests.post(
                self.webhook,
                json={
                    "msgtype": "text",
                    "text": {"content": f"[{level}] {msg}"}
                },
                timeout=3,
            )
        except Exception:
            pass  # ⚠️ 通知失败绝对不能往上抛异常，不能影响主交易流程
```

企微机器人 / 飞书机器人 / 邮件 / 短信 的写法都一样：继承 `Notifier`、实现 `push`、内部捕获异常。

### 第二步：在 main.py 里替换

打开 `main.py`，找到 `build_engine()`：

```python
def build_engine():
    broker = QmtBroker(Config.QMT_PATH, Config.ACCOUNT_ID)
    notifier = ConsoleNotifier()   # ← 把这行改掉
    ...
```

改成：

```python
from my_notifier import DingTalkNotifier

def build_engine():
    broker = QmtBroker(Config.QMT_PATH, Config.ACCOUNT_ID)
    notifier = DingTalkNotifier("https://oapi.dingtalk.com/robot/send?access_token=你的token")
    ...
```
### 第三步：重启验证

`python main.py`，用 curl 发送一条测试信号（或者让您的信号网关推送信号），看钉钉群里是不是收到了。

### 注意

- 框架内部所有"重要事件"都已经在调 `ctx.notifier.push(...)`：买入成功、买入失败、止盈卖出、撤单未确认等。换 Notifier 等于把这些事件全接到手机
- 通知量取决于策略：默认策略会在每次成交、每次止盈时推一次，盘中预计 3-10 条。如果觉得多，可以在自己的 Notifier 里按 level 过滤（比如只推 WARN/ERROR）

## D. 写自己的策略

**前提**：你看了默认策略的逻辑，觉得**算法范式跟自己想要的完全不同**——比如：
- 你想做 T+0 网格而不是分档累积
- 你想根据板块强度过滤信号
- 你想加止损（默认没有）
- 你想做收盘清仓

这时候才需要写策略。否则尽量调参数（B 档）。

下面分买入和卖出。

### D-1. 写自己的买入策略

#### 第一步：理解框架协议

每个买入策略继承 `BuyStrategy`，实现以下四个方法（`on_recover` 为可选实现）：

```python
class BuyStrategy(ABC):
    def should_accept(self, code) -> bool:
        """信号过滤。返回 False 则丢弃。默认全收。"""
        return True

    def on_init(self, task: BuyTask, ctx: StrategyContext) -> None:
        """信号首次到达时调用，在并发池里跑（多条信号互不阻塞）。"""

    def on_tick(self, task: BuyTask, ctx: StrategyContext) -> None:
        """ticker 周期推进，默认 3 秒一次，串行扫所有非 DONE 任务。"""

    def on_recover(self, task: BuyTask, ctx: StrategyContext) -> None:
        """【可选】灾备状态恢复与重构。系统重启接管任务时调用。"""
```

调用流程：

```
信号 sz000001 到达
    ↓
should_accept("sz000001")？返回 True 才继续
    ↓
框架建一个 BuyTask 放进任务表
    ↓
立即调 on_init(task, ctx)  ← 在并发池里跑
    ↓
on_init 决定：直接买完 → task.phase="DONE"
            进累积模式 → task.phase="ACCUMULATING"
            等回落    → task.phase="WATCHING"
    ↓
此后每 3 秒 ticker 触发一次 on_tick(task, ctx)
（你在 on_tick 里根据 task.phase 自己分发）
    ↓
某次 on_tick 里 task.phase="DONE" → 框架自动清理这个 task
```

#### 第二步：搞清楚 task 和 ctx 是啥

**`task` 是框架给你的"画板"**：

```python
@dataclass
class BuyTask:
    code: str           # 原始 code（如 sz000001）
    qmt_code: str       # QMT 格式（如 000001.SZ），下单用这个
    enter_time: datetime
    phase: str = "INIT" # ← 你的状态机标记，名字自定义
    data: dict = field(...) # ← 你的私有数据，存累积次数、上次买价等
```

关键：
- `phase` 你随便写名字（`"INIT"` / `"WATCHING"` / `"WAITING_BREAKOUT"` 都行），**只有 `"DONE"` 是约定的**——框架看到就清理
- `data` 是你的私人 dict，存什么都行，下一次 on_tick 还能拿到
- **不要给 `BuyTask` 加新字段**，怕跟框架未来字段冲突。要存什么放进 `task.data`

**`ctx` 是框架给你的"工具箱"**：

```python
ctx.broker      # 下单/查询，调用方法见 app/core/broker.py
ctx.notifier    # 推消息：ctx.notifier.push("INFO", "买入成功 xxx")
ctx.config      # Config 类，用 ctx.config.BUY_xxx 拿参数
ctx.now()       # 当前时间，方便后续做 mock 测试
```

#### 【核心难点】如何写重启接管 `on_recover`（可选）

如果你的策略需要维护中间状态（如累积买入次数、累计金额等），你必须实现 `on_recover` 方法，以防程序中途因各种原因重启后出现多买/少买。

**你不需要管的事情**：
- 你**不需要**写文件读取，框架已经在启动时帮你解析好了日志，并将属于本策略的 `BuyTask` 任务实例重新传递进来。
- 你**不需要**担心重买，因为框架在调用此钩子前，已经强制帮你在柜台**撤销了所有该票活跃的买单**。

**你需要实现的事情（套路代码）**：
1. 从 `ctx.broker.get_orders()` 拿到今天所有的委托记录。
2. 过滤出今日该股票、买入方向、且有成交量（`traded_volume > 0`）的真实订单。
3. 统计已买的总金额 and 总笔数，重新写入 `task.data`。
4. 如果已经买够了，将 `task.phase` 改为 `"DONE"`；否则改回运行时的状态（如 `"ACCUMULATING"`）。
5. **极其重要**：如果策略会向手机发送微信/钉钉成交通知，为了避免重启后把今天之前已经成交的单子再次弹窗通知，你需要为每笔历史订单创建一个 `BuyOrderTracker` 并在 `tracker.notified_volume = o.traded_volume` 设置已通知量，从而完美拦截重复通知。

**典型实现代码**：
```python
    def on_recover(self, task: BuyTask, ctx: StrategyContext) -> None:
        logger.info(f"开始重构 {task.code} 策略记忆")
        
        # 1. 查找柜台真实成交
        orders = ctx.broker.get_orders()
        my_orders = [o for o in orders if o.stock_code == task.qmt_code and o.is_buy and o.traded_volume > 0]
        
        if not my_orders:
            # 今天还没成交过任何单子，直接降级走全新初始化
            self.on_init(task, ctx)
            return
            
        # 2. 状态记忆重建
        s = _state(task) # 获取策略私有状态
        total_spent = 0.0
        s.buy_count = len(my_orders)
        
        for o in my_orders:
            fill_price = o.traded_price if o.traded_price > 0 else o.price
            total_spent += o.traded_volume * fill_price
            
            # 标记这些历史单已经通知过微信，防重启刷屏
            tracker = BuyOrderTracker(submit_time=time.time(), submit_chg=0.0)
            tracker.notified_volume = o.traded_volume
            s.order_trackers[o.order_id] = tracker
            
        s.total_bought = total_spent
        
        # 3. 判决恢复后的状态机流转
        if s.buy_count >= self.max_count or s.total_bought >= self.max_cap:
            task.phase = "DONE"
        else:
            task.phase = "ACCUMULATING" # 继续盯着未完成 of 委托
```

`ctx.broker` 常用方法：

```python
# 行情
quote = ctx.broker.get_stock_quote("000001.SZ")
# quote = {'last_price': 10.5, 'change_pct': 2.3, 'open': 10.4, 'high': 10.6, 'low': 10.3, 'last_close': 10.27, 'volume': 12345}
#         返回 None 表示拿不到，不要抛异常

# 账户
account = ctx.broker.get_account_info()
account.cash       # 可用资金

# 持仓
positions = ctx.broker.get_positions()  # List[PositionInfo]
for p in positions:

```

#### 第三步：写一个最简单的版本

举例：写一个"涨幅 3% 以内一笔买完，超过就放弃"的策略。

新建 `my_buy.py`：

```python
import logging
from app.config import Config
from app.strategy.buy_strategy import BuyStrategy, BuyTask, StrategyContext

logger = logging.getLogger(__name__)


class SimpleBuy(BuyStrategy):
    """涨幅低于 3% 一笔买 1 万元，否则放弃。"""

    MAX_CHG = 3.0
    AMOUNT = 10000

    def should_accept(self, code) -> bool:
        # 不买创业板
        if code.startswith("sz30"):
            return False
        return True

    def on_init(self, task: BuyTask, ctx: StrategyContext) -> None:
        quote = ctx.broker.get_stock_quote(task.qmt_code)
        if not quote:
            # 拿不到行情，下一轮 tick 重试
            return

        chg = quote['change_pct']
        if chg > self.MAX_CHG:
            logger.info(f"{task.code} 涨幅{chg:.2f}%>3%，放弃")
            task.phase = "DONE"
            return

        # 算量、下单
        price = quote['last_price']
        buy_price = round(price + 0.05, 2)
        volume = max(int(self.AMOUNT / buy_price / 100) * 100, 100)

        # 资金检查
        account = ctx.broker.get_account_info()
        if not account or account.cash < volume * buy_price:
            logger.warning(f"{task.code} 资金不足，跳过")
            task.phase = "DONE"
            return

        result = ctx.broker.buy(task.qmt_code, volume, buy_price)
        if result.success:
            ctx.notifier.push("INFO", f"买入: {task.code} {volume}股@{buy_price}")
        else:
            logger.warning(f"{task.code} 买入失败: {result.message}")

        # 一笔买完不管，标记结束
        task.phase = "DONE"

    def on_tick(self, task: BuyTask, ctx: StrategyContext) -> None:
        # 这个策略 on_init 就直接 DONE 了，不会进 ticker
        pass
```

#### 第五步：写一个带状态机的版本

刚才那个 SimpleBuy 太简单，没用上 ticker。下面演示一个"等回落"的策略：

```python
class WaitPullbackBuy(BuyStrategy):
    """涨幅 >5% 时等回落到 5% 以内再买，否则一笔买完。"""

    def on_init(self, task: BuyTask, ctx: StrategyContext) -> None:
        quote = ctx.broker.get_stock_quote(task.qmt_code)
        if not quote:
            return

        chg = quote['change_pct']
        if chg <= 5.0:
            self._buy(task, ctx, quote)
            task.phase = "DONE"
        else:
            # 进等待状态，等 ticker 来推进
            task.phase = "WATCHING"
            task.data['enter_chg'] = chg
            logger.info(f"{task.code} 涨幅{chg:.2f}%，等回落")

    def on_tick(self, task: BuyTask, ctx: StrategyContext) -> None:
        if task.phase != "WATCHING":
            return
        quote = ctx.broker.get_stock_quote(task.qmt_code)
        if not quote:
            return
        if quote['change_pct'] <= 5.0:
            self._buy(task, ctx, quote)
            task.phase = "DONE"
        # 否则继续等下一轮

    def _buy(self, task, ctx, quote):
        # ...同上 SimpleBuy 的下单逻辑
```

注意几点：
- on_init 里如果不直接结束，**记得设个有意义的 phase**（`"WATCHING"`/`"ACCUMULATING"` 等），让 on_tick 知道这只票当前在哪步
- on_tick 里要先 check phase，不同 phase 走不同分支
- 状态推进的判断条件要稳健：拿不到行情、价格异常都直接 return，等下一轮重试

### D-2. 写自己的卖出策略

卖出策略跟买入有**根本性区别**：**没有外部信号，自己一个 worker 线程定时干活**。

框架只管"叫你 start"和"叫你 stop"，中间你自己玩。

#### 第一步：理解协议

```python
class SellStrategy(ABC):
    def name(self) -> str:
        """策略名，框架日志用。默认用类名，无需重写。"""
        return self.__class__.__name__

    def start(self, ctx: StrategyContext) -> None:
        """启动自己的工作线程"""

    def stop(self) -> None:
        """停止工作线程"""
```

调用流程：

```
engine.run() 时框架调 strategy.start(ctx)
    ↓
你的线程 while running: sleep + 干活
    ↓
engine.stop() 时框架调 strategy.stop()
    ↓
你的线程看到 running=False 自然退出
```

#### 第二步：写一个止损策略

新建 `my_sell.py`：

```python
import logging
import threading
import time
from datetime import datetime, time as dtime

from app.config import Config
from app.strategy.buy_strategy import StrategyContext
from app.strategy.sell_strategy import SellStrategy

logger = logging.getLogger(__name__)


class StopLossSell(SellStrategy):
    """简单止损：当日跌幅 >= 5% 全部卖掉"""

    LOSS_THRESHOLD = -5.0
    POLL_INTERVAL = 5
    START_TIME = dtime(9, 30)

    def __init__(self):
        self._running = False
        self._sold = set()  # 今日已卖（避免一只票被卖两次）
        self._last_date = datetime.now().date()
        self._ctx: StrategyContext = None

    def start(self, ctx: StrategyContext) -> None:
        self._ctx = ctx
        self._running = True
        # 起一个 daemon 线程跑工作循环
        threading.Thread(target=self._loop, daemon=True, name="StopLossSell").start()
        logger.info(f"[{self.name()}] 已启动")

    def stop(self) -> None:
        self._running = False

    def _loop(self):
        """工作循环：每 N 秒扫一次持仓"""
        while self._running:
            time.sleep(self.POLL_INTERVAL)
            try:
                self._tick()
            except Exception as e:
                logger.error(f"[{self.name()}] 异常: {e}", exc_info=True)

    def _tick(self):
        # 跨日重置（每天新起一份"今日已卖"集合）
        today = datetime.now().date()
        if today != self._last_date:
            self._sold.clear()
            self._last_date = today

        # 9:30 之前不动
        if datetime.now().time() < self.START_TIME:
            return

        # 扫所有持仓
        for pos in self._ctx.broker.get_positions():
            if pos.is_today_buy or pos.can_use_volume <= 0:
                continue
            if pos.stock_code in self._sold:
                continue

            quote = self._ctx.broker.get_stock_quote(pos.stock_code)
            if not quote:
                continue

            if quote['change_pct'] <= self.LOSS_THRESHOLD:
                self._sell(pos, quote)

    def _sell(self, pos, quote):
        sell_price = round(quote['last_price'] * (1 - Config.SELL_DISCOUNT), 2)
        result = self._ctx.broker.sell(pos.stock_code, pos.can_use_volume, sell_price)
        if result.success:
            self._sold.add(pos.stock_code)
            self._ctx.notifier.push(
                "WARN",
                f"⚠️ 止损: {pos.stock_code} {pos.can_use_volume}股@{sell_price} "
                f"跌幅{quote['change_pct']:.2f}%"
            )
        else:
            logger.warning(f"[{self.name()}] 失败: {pos.stock_code} - {result.message}")
```

#### 第三步：注册到引擎

打开 `main.py`：

```python
from my_sell import StopLossSell

def build_engine():
    ...
    engine.register_sell_strategy(OpenHighSellStrategy())
    engine.register_sell_strategy(ProfitTierSellStrategy())
    engine.register_sell_strategy(StopLossSell())  # ← 加一行
    return engine
```

注册顺序不影响行为（每个策略各自跑各自的线程）。

#### 第四步：避免多卖

多个卖出策略并行跑时，**同一只票可能被多个策略同时盯上**。比如盈利止盈和止损都触发了，可能挂两次卖单。

防御做法：

1. 每个策略内部用 `self._sold` 集合做今日去重
2. 在调 `broker.sell` 前，**先 `broker.get_positions()` 查一次实时持仓**，发现 `can_use_volume <= 0` 就跳过

参考 `app/strategy/default/profit_tier_sell.py` 的 `_do_sell_tier` 实现。

## G. 常见问题

**Q：策略里发现 `task.phase` 怎么改都不生效？**
A：检查是不是创了新的 task 对象。框架认的是它内部 `_tasks[code]` 里那个引用，你直接 `task.phase = "X"` 就行，别 `task = SomeNewTask(...)`。

**Q：on_tick 里抛异常会怎样？**
A：框架兜底打 ERROR 日志，不影响其他任务。下一轮还会再调 on_tick，所以异常没自愈的话会反复打。

**Q：on_init 里抛异常会怎样？**
A：同样被兜底，但 task 已经进了任务表，状态停留在 `"INIT"`。下一轮 ticker 来时会调 on_tick（不会重新调 on_init）。所以 on_init 报错时记得手动 `task.phase = "DONE"` 让框架清理，否则就成了僵尸任务。

**Q：信号同一秒来 10 条会怎样？**
A：消费者立即把 10 条都派发到信号池（默认 8 个 worker），其中 8 条并行跑 on_init，剩下 2 条排队。一般几秒就处理完，不会丢。

**Q：策略想拿"市场环境"等外部数据怎么办？**
A：策略类构造时自己注入。在 `main.py` 里实例化：

```python
env = MarketEnv()  # 你自己的市场环境检测
engine.register_buy_strategy("default", MyBuy(env))
```

策略类构造函数 `__init__(self, env)` 接住即可。

**Q：能不能动态注册/卸载策略？**
A：当前不支持。要变就改 `main.py` 重启进程。低频场景下重启几秒钟，没必要做热加载。

**Q：HTTP 和 WebSocket 是什么关系？**
A：
- HTTP 始终启动（端口 30015），用于接收信号 + 查询管理
- WebSocket 需要配齐 `GATEWAY_HOST/PORT/TOKEN` 三个参数才启动
- 两者可以同时工作，互不冲突
- 两者均支持实盘生产环境：本地或局域网集成使用 HTTP 接口（被动推送模式）极具稳定性；跨网络或需要订阅信号网关时，使用 WebSocket（主动订阅模式）更为便捷
- 两者可以组合使用：例如通过 WebSocket 主动接收实时信号，同时通过 HTTP 接口对执行器进行任务查询、持仓查询或手动撤单等管理操作

**Q：HTTP 怎么调试？**
A：执行器启动后监听 30015 端口，自己用 curl 或 Postman 构造信号 POST 到 `/api/buy`：
```bash
curl -X POST http://localhost:30015/api/buy \
     -H "Content-Type: application/json" \
     -d "{\"code\":\"sz000001\"}"
```
看日志验证策略行为。盘中可以这么测试新策略，不用等真信号。

**Q：WebSocket 怎么连？**
A：将信号网关的 `GATEWAY_HOST/PORT/TOKEN` 填进 `app/config.py`，启动后执行器会自动作为客户端主动连接网关并订阅信号。如果您仅通过 HTTP 接口（被动推送模式）接收交易信号与进行管理，则无需配置这三项（保持默认的 `None` 即可）。
