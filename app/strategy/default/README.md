# 默认策略说明

这里是项目自带的**功能完整版默认策略**，开箱即用。`main.py` 默认装配的就是这一套。

包含三个策略：

| 文件 | 策略类 | 类型 | 触发时机 |
|---|---|---|---|
| `accumulate_buy.py` | `AccumulateBuyStrategy` | 买入 | 信号到达即触发 |
| `open_high_sell.py` | `OpenHighSellStrategy` | 卖出 | 9:30 开盘 |
| `profit_tier_sell.py` | `ProfitTierSellStrategy` | 卖出 | 盘中持续监控 |

参数都集中在 `app/strategy/default/stg_config.py` 里的 `StgConfig` 配置类中。

---

## 一、AccumulateBuyStrategy（分档累积买入）

### 核心思想

买入信号到达时，按当日涨幅决定买法：

- **涨幅低**：直接抢买（机会成本低）
- **涨幅中**：先建底仓 + 等回撤加仓（控制成本）
- **涨幅高**：等回落到合理区间再考虑（避免追高）

### 状态机

```
 INIT → 看涨幅
  │
  ├─ 涨幅 ≤ BUY_ONESHOT_THRESHOLD（默认 2.5%）
  │     └─ 一波流：积极重试买到为止 → DONE
  │
  ├─ BUY_ONESHOT_THRESHOLD < 涨幅 ≤ BUY_ACCUM_THRESHOLD（默认 4%）
  │     └─ 首笔保底仓 → ACCUMULATING
  │           └─ 每 3 秒看一次：当前价 ≤ 上次买价 × BUY_PULLBACK_RATIO（默认 0.98）
  │                 └─ 触发加仓，按档位表买
  │                       └─ 达到买入次数上限或总额上限 → DONE
  │
  └─ 涨幅 > BUY_ACCUM_THRESHOLD
        └─ WATCHING：等回落
              └─ 每 3 秒看一次：回到 3.5% 以内
                    └─ 转入 ACCUMULATING
        └─ 涨幅持续高 → 等到 BUY_DEADLINE（默认 14:50）自动 DONE
```

### 档位表（BUY_ACCUM_TIERS）

```python
BUY_ACCUM_TIERS = [
    (2.0, 1000, 3000),    # 模拟均价 ≤ 2%：单笔 1 千、总额上限 3 千
    (3.0, 1000, 2000),    # 2% < 均价 ≤ 3%：单笔 1 千、总额上限 2 千
    (4.0, 1000, 1000),    # 3% < 均价 ≤ 4%：单笔 1 千、总额上限 1 千
]
```

**模拟均价**：把已买的所有涨幅做算术平均得到。涨幅越高，加仓越保守。

### 下单与自愈工程化

1. **执行模式**：
   * **一波流**：信号到达且涨幅极低时触发，通过独立线程进行 `max_retry=3` 次积极撤单重挂（扫主卖上方），务求瞬间买入。若一波流结束但实际买入成交额未吃足额度（未达到 `BUY_ONESHOT_FILL_RATIO` 默认 90% 比例），策略**不会直接 DONE，而是降级为累积模式**，在后续的日内回撤中继续加仓。
   * **首笔与加仓**：全部采用**异步佛系发单**（`max_retry=0`），直接发单不阻塞主线程。

2. **自愈与风控逻辑**：
   * **等同步（丢单自愈）**：发单后若订单未及时出现在委托列表中，在 `BUY_SYNC_TIMEOUT`（默认 10.0 秒）内会进入拦截等待；若超时未同步则判定为柜台丢单，自动清除该委托记录并触发下一次加仓重挂。
   * **废单自愈**：如果挂单被柜台拒绝为废单（Rejected），自动从追踪列表中剔除，实现无感自愈重挂。
   * **活跃单拦截**：如果上一笔挂单仍处于活跃未结案状态，会自动拦截后续加仓，防止资金未解冻或超买。
   * **防骗炮保护**：当现价跌破开盘价的守卫线（`BUY_FAKE_BREAKOUT_RATIO` 默认 0.995，即跌破开盘价 0.5%）时，判定为骗炮强砸，停止一切后续加仓，直接 `DONE` 退出。

### 参数清单

| 参数 | 默认值 | 说明 |
|---|---|---|
| `BUY_ONESHOT_THRESHOLD` | 2.5 | 一波流抢买阈值（%） |
| `BUY_ONESHOT_AMOUNT` | 3000 | 一波流单笔金额（元） |
| `BUY_ONESHOT_FILL_RATIO` | 0.9 | 一波流最低足额成交比例，不足则降级 |
| `BUY_ACCUM_THRESHOLD` | 4.0 | 累积模式阈值（%），>此值进 WATCHING |
| `BUY_ACCUM_TIERS` | 见上 | 累积分档档位表 |
| `BUY_MAX_COUNT` | 3 | 最大买入次数 |
| `BUY_PULLBACK_RATIO` | 0.98 | 加仓回撤比例 |
| `BUY_PRICE_PREMIUM` | 0.05 | 挂单溢价（元，扫卖一上方） |
| `BUY_FAKE_BREAKOUT_RATIO` | 0.995 | 骗炮拦截比例（当前价 ≤ 开盘价 × 此比例时强制 DONE 退出） |
| `BUY_SYNC_TIMEOUT` | 10.0 | 柜台订单同步超时时间（秒，丢单自愈时限） |

### 默认过滤

`should_accept` 默认拒绝创业板（code 以 `sz30` 开头）。要改去 `accumulate_buy.py` 修改 `should_accept` 函数。

## 二、OpenHighSellStrategy（高开止盈）

### 核心思想

昨日持仓如果今天**高开 ≥ 阈值**（默认 3%），开盘瞬间集合竞价就给了你一个免费的好价位，立刻挂卖锁住一部分利润。

### 时序

```
9:29 进入准备阶段
  ├─ 扫昨日持仓 + 行情
  ├─ 算每只票的开盘涨幅 = (open - last_close) / last_close
  └─ 涨幅 ≥ OPEN_HIGH_CHG（默认 3%）→ 加入 pending 列表
        └─ 计算卖出量 = 可卖量 × OPEN_HIGH_SELL_RATIO（默认 50%）
        └─ 计算卖出价 = open × (1 - SELL_DISCOUNT)（默认 1.9% 折价）

9:30 ~ 9:30:02 高频自旋等待精确时刻

9:30:02 一次性触发执行
  └─ 每只票一个独立线程并发挂卖（开盘抢跑，互不阻塞）
        └─ 每只票：发单 → 等撮合 → 未成交撤单（如果是废单免等待直接重试；若部分成交对账仅重挂剩余） → 等解冻 → 重挂
              └─ 最多重试 10 次（防丢单超时时限 10 秒）
```

### 为什么 9:30:02 不是 9:30:00

开盘瞬间交易所最拥堵：撮合排队、状态切换、价格波动剧烈。延迟 2 秒避开峰值，成交率更高、价格更稳定。

### 折价为什么 1.9%

价格笼子（涨跌幅限制）边界是 2%，挂 1.9% 是**留 0.1% 安全垫**避免触碰边界被废单。

### 参数清单

| 参数 | 默认值 | 说明 |
|---|---|---|
| `OPEN_HIGH_CHG` | 3.0 | 高开阈值（%） |
| `OPEN_HIGH_SELL_RATIO` | 0.5 | 卖出比例 |
| `OPEN_HIGH_PREPARE_TIME` | 9:29 | 准备开始时间 |
| `OPEN_HIGH_EXECUTE_TIME` | 9:30:02 | 触发时间 |
| `SELL_DISCOUNT` | 0.019 | 折价比例 |

## 三、ProfitTierSellStrategy（分档盈利止盈）

### 核心思想

盘中盯昨日持仓，按当日涨幅**分档卖出**：达到第一档涨幅卖一部分，达到第二档再卖一部分，最后一档卖完剩余。

### 时序

```
9:30 后初始化任务表
  ├─ 加载昨日持仓
  ├─ 排除今日新买入的（不能 T+0 卖）
  ├─ 排除已被高开止盈卖掉的
  └─ 每只票按 SELL_PROFIT_TIERS 预算分档卖出股数

每 SELL_POLL_INTERVAL（默认 3 秒）扫一次
  ├─ 扫描当前各档活跃委托状态，进行增量成交与自愈对账：
  │     ├─ 若有新成交：更新对应分档的已成交股数，并推送通知
  │     ├─ 若废单（Rejected）或同步超时（SELL_SYNC_TIMEOUT）：自动剔除并允许重新补单挂卖
  ├─ 根据当前最新涨幅命中档位索引
  └─ 遍历所有已命中的档位，如该档实际成交数不足且目前无活跃委托：
        └─ 增量补单：以当前价 × (1 - SELL_DISCOUNT) 计算折价，挂单卖出该档剩余股数
  └─ 所有档位目标成交量均已卖足 → DONE
```

### 档位表（SELL_PROFIT_TIERS）

```python
SELL_PROFIT_TIERS = [
    (3.0, 0.5),    # 涨幅达 3%，卖 50%
    (5.0, 0.5),    # 涨幅达 5%，卖剩余全部的 50%
    (8.0, 1.0),    # 涨幅达 8%，卖剩余全部
]
```

最后一档自动算"卖完剩余股数"，不管 ratio 设的多少。所以你想分三档就这么写：

```python
SELL_PROFIT_TIERS = [
    (3.0, 0.3),
    (5.0, 0.4),
    (8.0, 1.0),
]
```

### 跨档触发

如果某次扫描时涨幅一下子从 4% 跳到 9%，会对已命中的两档同时触发计算。若此前未下单，会并发增量补单挂出，不会跳过中间档。

### 防超卖与对账

* 每次卖出前先 `broker.get_positions()` 实时查一次持仓。如果 `can_use_volume = 0`（已被手动卖光、被高开止盈卖完等），跳过对应分档并将该档成交记录标满，防止后续卡住。

### 参数清单

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SELL_PROFIT_TIERS` | 见上 | 分档表 |
| `SELL_POLL_INTERVAL` | 3 | 扫描间隔（秒） |
| `SELL_PROFIT_START_TIME` | 9:30:30 | 开始监控时间 |
| `SELL_DISCOUNT` | 0.019 | 折价比例 |
| `SELL_SYNC_TIMEOUT` | 10.0 | 卖出委托单柜台同步超时时间（秒，丢单自愈时限） |

## 三策略协作

三个策略各跑各的，互不耦合：

```
9:29 ─── OpenHigh 准备
9:30 ─── OpenHigh 等触发
9:30:02  OpenHigh 一次性卖完高开票
9:30:30  ProfitTier 加载持仓开始监控
9:30 ~ 14:50（BUY_DEADLINE） AccumulateBuy 收到信号立即处理（盘前也接收，盘中持续接收）

9:30 ~ 收盘 ProfitTier 持续监控
```

**避免重复卖**：ProfitTier 的 `_load_positions` 不会加载今日新买的票（`is_today_buy`），这样累积买入的票当天不会被止盈卖掉。

OpenHigh 卖完后，ProfitTier 下次扫到那只票时 `can_use_volume` 已经减少，不会重复卖。

## 怎么改

### 只改参数

去 `app/strategy/default/stg_config.py` 改对应常量，重启 `python main.py`。

### 改逻辑

直接编辑 `default/` 下面对应文件。这里的代码是**普通策略代码**，没有特殊保护，改完重启就生效。

### 写完全不同的策略

不要直接覆盖 `default/`，**新建文件**继承 `BuyStrategy` / `SellStrategy`，在 `main.py` 里替换注册。详见 `doc/定制开发指南.md`。
